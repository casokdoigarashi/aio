# AIO観測の拡張計画（多社展開を前提に）

2026-11-19 起案。デスクトップの `ARIGATO-AIO-Automation`（Googleスクショ取得）と
本リポジトリ（API観測・レポート）をどう統合するかの設計案。

## 0. 結論から

**新規に作らず、本リポジトリを土台にする。** 理由:

| すでにあるもの | 場所 |
|---|---|
| 4エンジン（AIモード/Gemini/Claude/ChatGPT）への質問と回答取得 | `scripts/auto_check.py` |
| ブランド出現判定（◎筆頭/○リスト内/△引用のみ/×なし） | `scripts/lib_common.py` |
| 引用元ドメインの抽出と分類（自社/関連/その他） | 同上 |
| 競合名の検出 | 同上 |
| 回答本文の保存 | `data/observations/*.yml` |
| 週次レポート生成 | `scripts/analyze.py` |
| 毎週火曜の自動実行 | `.github/workflows/weekly-aio-check.yml` |
| **2026年7月からの時系列データ**（19週分） | `data/observations/` |

特に最後が重要。**定点観測は時系列が資産**で、作り直すと比較が切れる。

### 役割分担

| | 担当 | 理由 |
|---|---|---|
| **デスクトップ**（`ARIGATO-AIO-Automation`） | Google AIモードのスクリーンショット | Googleは自動検索を規約で認めていない。人のPCのブラウザで撮る形は残す。証跡としての価値もある |
| **クラウド**（本リポジトリ / GitHub Actions） | API観測・集計・スプレッドシート出力・レポート | 毎週確実に動く。PCの電源状態に依存しない |

デスクトップ側は**スクショ専用**にし、そこから項目を読み取る処理はクラウド側に寄せる
（スクショをDriveに上げる → クラウドが読む、または SerpApi の `google_ai_mode` で
テキストを取る。後者はすでに動いている）。

## 2. 繰り返し取得（新規要件）

AIの回答は毎回変わるため、**同じ質問を1週に n 回聞いて「n回中何回出たか」で記録する。**

- 既定 **n = 3**（費用と安定性のバランス。後述の見積もりもこれが前提）
- 記録は `hits / trials` と出現率（%）
- 順位（何番目に出たか）は**試行ごとに記録し、週の代表値は最良値と平均の両方**を持つ

n=3 だと出現率は 0% / 33% / 67% / 100% の4段階になる。細かく見たいなら n=5
（0/20/40/60/80/100）だが、費用は 1.7 倍になる。**まず n=3 で始めて、
値が飽和するようなら上げる**のが妥当。

## 3. スプレッドシートの形

Googleスプレッドシート1ファイル。**会社ごとに別ファイル**にして混在を防ぐ。

### シート1: `runs`（生ログ。1行 = 1質問 × 1エンジン × 1試行）

| 列 | 内容 |
|---|---|
| date | 観測日（週の基準日） |
| client_id | 会社ID（`arigato_living` など） |
| query_id | q1〜q30 |
| query_text | 質問文（変更検知のため毎回記録） |
| engine | google_ai_mode / gemini / claude / chatgpt |
| model | 実際に使われたモデルID |
| trial | 1〜n |
| brand_mentioned | TRUE / FALSE |
| position | featured / listed / cited_only / none |
| rank | 回答内で何番目に挙がったか（挙がらなければ空） |
| rank_total | その回答で挙がったスタジオの総数 |
| own_cited | 自社ドメインが引用されたか |
| related_cited | 関連メディアが引用されたか |
| cited_domains | 引用元ドメイン（カンマ区切り） |
| competitors | 名前が出た競合（カンマ区切り） |
| answer_text | 回答本文（あとで見返す用） |
| error | 取得できなかった場合の理由 |

**「取得できず」も1行として残す。** 空欄と失敗は意味が違う。

### シート2: `weekly`（週次集計。1行 = 週 × 質問 × エンジン）

date / client_id / query_id / engine / trials / hits / hit_rate / best_position / mean_rank

### シート3: `citations`（引用元の週次集計）

date / client_id / query_id / engine / domain / count / domain_class（own / related / competitor / other）

**ここが一番効く。** 「AIがどのページを読んで答えているか」が分かると、
打ち手が「記事を書く」か「そのメディアに載る」かに分岐する。

### シート4: `competitors`

date / client_id / competitor / mention_count / share_of_voice

### シート5: `social`

date / client_id / platform / account / post_id / posted_at / metric / value

- Instagram: 投稿ごとの reach / saved / likes / comments
- 競合アカウント: follower_count / media_count のみ（公開値）
- Google Trends: キーワードごとの相対指数

### シート6: `heatmap`（表示用）

縦に質問（q1〜q30）、横に週。値は出現率。条件付き書式で色の濃淡。
`weekly` から数式またはスクリプトで生成する。

## 4. 費用の見積もり

**Perplexityは採用しない（2026-11-19 決定）。** エンジンは現行の4つのまま。

### 前提

- 30問 × n=3回 × APIエンジン3つ（Gemini / Claude / ChatGPT）= **270回/週** ≒ 1,170回/月
- Google AIモード（SerpApi）は 30問 × 1回 = 30回/週 ≒ 130回/月
- エンジンごとでは **390回/月**

### 単価（**要確認**。公式ページ以外の情報が割れている）

| サービス | 検索・グラウンディング料 | トークン料 |
|---|---|---|
| OpenAI web_search | $10 / 1,000回（2026年4月に$25から改定との情報） | 別途モデル単価 |
| Gemini グラウンディング | **月5,000回まで無料**、超過 $14 / 1,000回（Gemini 3系） | 別途モデル単価 |
| Claude web search | 別途 | **claude-opus-5 は入力 $5 / 出力 $25 per 1Mトークン** |
| SerpApi | 無料プラン 月250検索 | — |

### 概算（1社あたり / 月）

| エンジン | 回数/月 | 概算 | 備考 |
|---|---|---|---|
| Gemini | 390 | **$2〜5** | グラウンディングは無料枠5,000/月に収まる |
| ChatGPT | 390 | **$9〜14** | 検索 $3.9 ＋ トークン |
| **Claude** | 390 | **$60〜115** | **←これが支配的** |
| SerpApi | 130 | $0 | 無料枠内 |
| 合計 | | **$75〜135／月** | |

### 費用の主因は Claude（Opus）

Claudeは web search で1クエリあたり **13〜19件** の情報源を読んでいる（実測値）。
その本文が入力トークンになるため、1回あたり $0.15〜0.30 程度かかる。
**Opus は入力 $5 / 出力 $25 per 1Mトークンで、他エンジンより1桁高い。**

質問を10問→30問、試行を1回→3回にすると **9倍**になる。
8月と10月にAnthropicのクレジットが枯渇した経緯を踏まえると、ここは設計で吸収すべき。

### 推奨：Claudeだけ n=1 のままにする

| エンジン | 試行回数 | 月額 |
|---|---|---|
| Gemini | n=3 | $2〜5 |
| ChatGPT | n=3 | $9〜14 |
| **Claude** | **n=1** | **$20〜39** |
| SerpApi | n=1 | $0 |
| **合計** | | **$31〜58／月** |

理由:

- 繰り返し取得の目的は**ばらつきの平準化**。安いエンジンで取れれば足りる
- Claudeは2026年7月から **n=1 で19週分の時系列**がある。
  n=1 を維持するほうが**過去データとの比較が切れない**
- モデルを安いものに変える案は却下。**同じ質問に同じモデルで答えさせる**のが
  定点観測の前提で、モデルを変えると測っている対象自体が変わる

### まず実測で校正すること

上記のClaude見積もりは「引用元13〜19件」から逆算した概算。
**Anthropic Console の利用履歴で、直近1ヶ月の実際の金額を確認すれば精度が上がる。**
現在は 10問 × n=1 × 週1回 = 月43回なので、その実績を9倍すれば
30問 × n=3 の金額が出る。②に進む前に一度見ておきたい。

### 感度

| 条件 | 月額の目安 |
|---|---|
| 30問 / Claude n=1・他 n=3（**推奨**） | $31〜58 |
| 30問 / 全エンジン n=3 | $75〜135 |
| 30問 / 全エンジン n=1 | $25〜45 |
| **5社に展開（推奨構成）** | **$155〜290／月** |

多社展開では SerpApi の無料枠（月250）を超えるため、**2社目から有料プラン**が必要。

## 5. 多社展開の形

```
clients/
  arigato_living/
    config.yml          # ブランド・別名・自社ドメイン・競合・質問セット・SNSアカウント
    secrets.example     # 必要な環境変数の名前だけ（値は入れない）
  other_company/
    config.yml
data/
  arigato_living/
    observations/*.yml
    reports/
  other_company/
    observations/*.yml
    reports/
```

- 実行時に `--client arigato_living` で切り替える
- **データディレクトリを会社ごとに分ける**ので混在しない
- スプレッドシートも会社ごとに別ファイル。IDを `config.yml` に持つ
- APIキーは共通（自社のキーで全社分を回す）。SNSトークンは会社ごとに別なので
  `INSTAGRAM_TOKEN_<CLIENT_ID>` のように環境変数名を分ける

既存の `config/config.yml` は `clients/arigato_living/config.yml` に移し、
互換のため当面は旧パスも読めるようにする。

## 6. 進め方

ご指定の順番どおり。各段階の完了条件を決めておく。

| 段階 | 内容 | 完了条件 |
|---|---|---|
| ① | 質問セットとスプレッドシートの形 | 30問を `config.yml` に追加。シート6枚の列が確定 |
| ② | 3エンジンへの質問と記録 | 手動で1回通し、`runs` シートに270行入る |
| ③ | ヒートマップと週報 | 質問×週の色分けが出る。週次の変化が1ページで読める |
| ④ | Instagram・Googleトレンド | `social` シートに数字が入る |
| ⑤ | 自動実行と多社切り替え | 毎週火曜に全社分が動く |

### ①の前に確認が必要なこと

1. **デスクトップの `capture.mjs` と設定**を読みたい（PCフォルダの登録、または貼り付け）
2. **Instagram**: `@arigatoliving39` が
   - プロアカウント（ビジネス／クリエイター）になっているか
   - Facebookページと連携しているか
   - 連携していない場合、Graph APIでは投稿ごとのリーチ・保存が取れない
3. **質問セット30問**の内容確認（上記A〜Fでよいか、外したい/足したいものがあるか）
4. **繰り返し回数**: Gemini・ChatGPT は n=3、**Claude は n=1 のまま**でよいか
5. **Anthropic Console の直近1ヶ月の利用金額**（Claudeの見積もりを実測で校正したい）

### 規約について

- **Googleの検索結果を自動取得することは、Googleの規約で認められていない。**
  デスクトップ側の人の操作によるスクショは残し、機械での取得は SerpApi
  （Googleの結果を正規に再配布しているサービス）経由に限る
- 取得できなかった週は `error` 列に理由を残し、**ほかのエンジンは止めない**。
  これは本リポジトリで実装済み（`failure_reason()`）
- 競合アカウントの数値は**公開されている範囲のみ**。非公開のインサイトは取らない
