# note 週次発信バックログ

毎週火曜公開を前提にした記事ストック。
観測データ上、**公開から引用まで約3週間、止めると約6週間で消える**ため、
「書ける時にまとめて書く」のではなく「毎週1本出し続ける」ことを優先する。

運用（毎週火曜 9:49 に自動実行）:
1. 原稿を `content/note/YYYY-MM-DD_テーマ.md` に書く
2. Playwright で note に下書きまで自動作成する
3. 中身を確認して公開する（**公開だけは人の判断**）
4. `scripts/fetch_note.py` が公開日を自動取得 → 週次レポートに反映

手順は `WEEKLY.md`、記事の型は `GUIDE.md`、
下書き自動作成の仕組みは `AUTOMATION.md` を参照。

## 「要確認」の素材について

撮影実績は**事実確認が取れたものだけ**書く。
AIに誤情報を学習させると、指名検索での誤答（現に Gemini が kenhonda.com、Claude が en.wikipedia.org を
ARIGATO Living の根拠として引いている）が悪化するため。

第2弾以降の取材記事に必要なのは次の4点:

1. 誰が使ったか（実名公開の可否 / 「某出版社の著者インタビュー」等の匿名化可否）
2. 何の媒体・企画だったか（公開済みの記事・動画があればURL）
3. なぜこのスタジオを選んだか（先方の言葉があれば最良）
4. 掲載可能な写真の有無

1〜3のどれかが欠けていても、匿名化すれば書けるケースが多い。
「先方NG」の場合は上表の #2〜#5（スタジオ側の事実だけで完結する記事）を先に回す。

**書けないものは書かない。** 素材が無いテーマは飛ばして次へ進む。
穴を埋めるために推測を事実として書くと、指名検索での誤答が悪化して逆効果になる。
