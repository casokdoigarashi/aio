# note週次発信の実行手順

毎週火曜の朝に自動実行される。この手順書のとおりに進めること。

観測データ上、**公開から引用まで約3週間、止めると約6週間で引用が消える**。
だから「良い記事を時々」ではなく「毎週1本」を優先する。
素材が足りない週も、スタジオ側の事実だけで書ける記事に切り替えて必ず1本出す。

## 1. 現状を確認する

```
python scripts/fetch_note.py
```

`data/note_articles.yml` に公開済み記事が入る。
直近の公開日を見て、何週止まっているかを把握する。

## 2. テーマを決める

`content/note/BACKLOG.md` の表を上から見て、まだ書いていないテーマを1つ選ぶ。

- **「必要な素材」が「不要」のものを優先する**
- 撮影実績もの（#8など）は、実名公開の可否・媒体・公開済みURLが
  揃っているときだけ書く。揃っていなければ飛ばして次へ

## 3. 原稿を書く

`content/note/GUIDE.md` の型に従う。タイトル・本文構成・禁止事項はそこに書いてある。

### 事実の出典は次の3つだけ

| 出典 | 内容 |
|---|---|
| 公式サイト | https://www.a-ms2.com/arigatoliving/studio/kagurazaka/ |
| R-Studio掲載ページ | https://www.rstudio.co.jp/studio/113049/ |
| 公開済みのnote記事 | https://note.com/casokdo_note |

**この3つに書かれていないことは書かない。**
撮影実績・利用者名は、すでに公開されているもの以外は使わない。
AIに誤情報を学習させると指名検索での誤答が悪化する（実際に Gemini が
kenhonda.com、Claude が en.wikipedia.org を ARIGATO Living の根拠として
引いている状態なので、ここを濁らせない）。

迷ったら書かない。推測を事実として書くくらいなら、その段落を削る。

### 保存先

`content/note/YYYY-MM-DD_テーマ.md`（公開予定日の日付）

## 4. 画像を選ぶ

公式サイトのギャラリー写真を使う。

```
https://www.a-ms2.com/arigatoliving/cms/wp-content/uploads/2023/05/19_st_kagra_slidesNN_L.jpg
```

NN は 01〜14。`content/note/images/` にすでにある分はそのまま使う。

| ファイル | 内容 |
|---|---|
| 01_メインフロア_自然光 | 窓・自然光・ダイニング・無垢材 |
| 02_カーテン越しの自然光 | ソファとカーテン越しのやわらかい光 |
| 03_北欧家具とデスク | セブンチェア、フロアランプ、左官壁 |
| 04_メイクルーム | 洗面台と丸鏡 |
| 05_カウンターキッチン | IHキッチンと奥への抜け |

足りなければ 01〜14 から落として中身を見て選ぶ（slides02=左官壁、
07〜09=エントランス、10=仕切りカーテン、12=レストルーム、13=バリアフリー、
14=ソファのある広いメインフロア）。

原稿には次の形で書く。**段落の切れ目に置くこと**（箇条書きの途中は避ける）。

```
![キャプション](images/01_メインフロア_自然光.jpg)
```

3〜5枚が目安。本文の主張と一致する写真だけを選ぶ。

## 5. 下書きを作る

原稿をコミットしたうえで、`.github/run-note-draft` を書き換えてpushする。

```
content/note/2026-11-04_新しい原稿.md
```

**新しい記事なので、上書き先URL（https://editor.note.com/…）は書かない。**
書くと前回の記事を潰してしまう。

## 6. 結果を確認する

Actions の「note下書き作成」のログで次を確認する。

- `見出し N個` … **0個なら書式が失われている**。やり直す
- `画像 N/N枚` … 枚数が一致しているか
- `保存の確認（再読み込み後）` … 本文が保存されているか

失敗したら Artifact のスクリーンショットとログのDOMダンプを見て直す。
note のUI変更でセレクタがずれるのはよくあること。

直せなかった場合は、**原稿だけコミットして残し、手で貼れる状態にして報告する**。
自動化が通らないことより、発信が止まることのほうが問題。

## 7. 記録して報告する

1. できた下書きURLを `.github/run-note-draft` の上書き先として書き、pushする
   （以降の修正が新規作成ではなく上書きになる）
2. `content/note/BACKLOG.md` の状況表に1行足す
3. 下書きURLを添えて報告する

## やらないこと

- **公開しない。** 下書きまで。公開の判断は人がする
- 見出し画像（サムネイル）の設定もしない（自動化していない）
- 画像のキャプション入力もしない（同上）
